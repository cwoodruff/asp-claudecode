# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build & Run Commands

```bash
# Build entire solution
dotnet build

# Run web app (http://localhost:5155, https://localhost:7038)
dotnet run --project src/Intelligently.Web

# Run admin app (http://localhost:5001, https://localhost:7263)
dotnet run --project src/Intelligently.Admin

# Run all tests
dotnet test

# Run a single test project
dotnet test tests/Intelligently.UnitTests/
dotnet test tests/Intelligently.IntegrationTests/

# Run tests with coverage
dotnet test /p:CollectCoverage=true

# Run only the evaluation harness (stored trace fixtures replayed through the rubric)
dotnet test tests/Intelligently.IntegrationTests/ --filter Category=Eval
```

## Architecture

This is **Intelligently**, an ASP.NET Core 10 AI-powered tutoring platform using Claude (official `Anthropic` NuGet SDK). It follows a layered architecture:

- **Intelligently.Core** — Domain entities and interfaces. No external dependencies. Contains `IAnthropicService` and all AI domain entities (AIConversation, AIMessage, AIEscalation, AIKnowledgeEntry, AIAnalyticsEvent) in `Entities/AI/`.
- **Intelligently.Infrastructure** — Data access (EF Core 10 + SQL Server) and external services. `AnthropicService` wraps the official Anthropic SDK (`client.Messages.Create` / `CreateStreaming`); the SDK's built-in retry handles 408/409/429/5xx, so there is no Polly wrapper. A `refusal` stop reason throws `AIRefusalException` (Core). `IntelligentlyDbContext` extends `IdentityDbContext`.
- **Intelligently.Web** — Main Razor Pages app. Configures rate limiting (both partitioned by the authenticated user id, so `UseAuthentication` runs before `UseRateLimiter`: `chat` policy sliding window 10/min for chat and `POST /agent/runs`, 120 reqs/min global), DI for the Anthropic client/service, and OpenTelemetry (ActivitySource `Intelligently.Agents`; console exporter in Development, OTLP via `Otel:Endpoint` otherwise).
- **Intelligently.Admin** — Admin portal (Razor Pages).

Dependency flow: Web/Admin → Infrastructure → Core.

## Key Patterns

- **AI integration**: `IAnthropicService` (Core) / `AnthropicService` (Infrastructure) supports both streaming (`IAsyncEnumerable<string>`) and non-streaming completions. Default model for both paths is `claude-opus-5-5` (adaptive thinking); `AnthropicService.CheapModel` (`claude-haiku-5-5`) is for cheap routes.
- **Escalation workflow**: AI conversations can escalate to instructors; resolved escalations can feed back into the knowledge base (`AIKnowledgeEntry`).
- **Rate limiting**: Built-in ASP.NET Core 10 rate limiter (no external packages). Named policy `chat` with sliding window.
- **Frontend**: htmx (jQuery and Bootstrap were removed).

## Required Runtime Configuration

- `ConnectionStrings:DefaultConnection` — SQL Server connection string
- `Anthropic:ApiKey` — Anthropic API key (validated at startup)
- `Otel:Endpoint` — OTLP collector endpoint (non-Development only)

## Autonomous Agent Runtime (Phases 1–4)

Spec: `docs/autonomous-agent-plan.md` (five planes, seven-stage conditional state graph, transition table in section 2.2).

- **Core/Agents** — `Contracts/` (IReasoningEngine, IContextAssembler + PromptEnvelope/PromptMessage/PromptContent/PromptSection, IKnowledgeRetriever, IEpisodicMemoryStore, IPromptTokenCounter, IEpisodeSummarizer, TaskText, IToolDispatcher, IPolicyDecisionPoint + PolicyRequest/PolicyDecision, PolicyRule, RunPrincipal, IIdempotencyBarrier, IToolRateLimiter, IApprovalGate, IEvidenceSink, IRunQueue), `Entities/` (AgentRun with an owned `Principal`, AgentStep with `ResponseContentJson`/`PromptTokens`, AgentPlan with `ResponseContentJson`, AgentTrace, AgentEpisode with `TaskText`/`Embedding`, AgentApproval, IdempotencyRecord), `StateGraph/` (AgentStage, StageOutcome, StageTransitions table, RecoveryBudget owned type, IStageHandler), `Tools/` (ToolDescriptor with optional `CourseScopeArgument`, ToolCall, ToolResult with `ErrorKind`, ToolRiskLevel, CanonicalJson, IToolHandler, IToolRegistry), `AgentsOptions`.
- **Infrastructure/Agents** — `StateGraph/StateGraphRunner` executes one stage per `StepAsync`/`TryStepAsync`, rejects any edge not in `StageTransitions`, commits after every stage; before the handler runs it claims the run with one conditional `ExecuteUpdateAsync` (`ClaimedBy` = the `IWorkerIdentity` id, `ClaimedUntil` = now + `Agents:StageLeaseSeconds`) that only matches a Running run with no live lease, returns `Executed = false` without executing anything when the claim fails, releases the lease in the commit (success or failure; a best-effort conditional release covers cancellation and lost races), and `ClaimedUntil` is a second concurrency token so a worker whose expired lease was taken over cannot commit its stale stage; `ProcessWorkerIdentity` (`{machine}/{pid}`) is the default `IWorkerIdentity`; `StateGraph/Handlers/` one handler per stage including `AwaitingApprovalHandler`; `RunQueue` (bounded `Channel<Guid>`); `Intelligence/AnthropicReasoningEngine` (beta messages endpoint; structured output from the `AgentPlan` record schema; the tool list is sent on every stage with `tool_choice: none` for Plan/Judge and `auto` for Act; adaptive thinking; a `compaction` stop continues the turn with the response content appended) and `Intelligence/PromptEnvelopeMapper` (envelope → SDK types, cache breakpoints as `cache_control`); `Execution/` (ToolRegistry, ToolDispatcher, `lookup_knowledge` over the retriever); `Control/` (rule-driven `PolicyDecisionPoint`, `IdempotencyBarrier`, `ToolRateLimiter`, `ApprovalGate`); `Evidence/` (see Evidence Plane below); `Learn/` (`EpisodeWriter`, `EscalationResolver`, see Learn below); `Context/` (see Context Plane below). Register everything with `services.AddAgentRuntime(configuration)`.
- **Control Plane** — `PolicyDecisionPoint` evaluates `Agents:Policy:Rules` in a fixed order: identity (no principal → Deny; course-scoped call outside the principal's enrolment → Deny; role requirements), risk gate (ReadOnly Allow, Mutating allowed inside the run's course, Destructive/External RequireApproval; a recorded approval for the same run+tool+args hash satisfies the gate; no matching rule fails closed to RequireApproval), rate limit (`ToolRateLimiter`, sliding windows per run and per user from the rules, separate from the HTTP limiter; exceeded → Deny), idempotency (covered calls keyed on `(RunId, ToolName, SHA-256(canonical args))`; a replay returns the stored result without executing; only successful results are stored). Deny is final for that call: Verify sets `RecoveryReason = PolicyDenied` and Recover replans without retrying. RequireApproval parks the run (step status `AwaitingApproval`, `AgentApproval` row, `AIEscalation` for instructors); `IApprovalGate.DecideAsync` records the decision as an `Approval` trace, resolves the escalation, sets the run back to Running and re-enqueues it. Approved resumes the same Act step with the parked calls (no new model turn); denied goes to Recover then Plan with `PlanRevision + 1`.
- **Context Plane** — `ContextAssembler.BuildAsync(run, stage)` builds the `PromptEnvelope` stable-to-volatile: frozen system block (cache breakpoint) → name-sorted tools (breakpoint on the last) → `Knowledge` message (header block + one block per retrieved entry) → `Episodic` message (header + one block per episode) → `Transcript` (task; per revision the plan as an assistant turn replayed from `AgentPlan.ResponseContentJson` plus a user acknowledgement; per finished step the assistant turn replayed verbatim from `AgentStep.ResponseContentJson`, else synthesized from text + tool calls, followed by a user message with one `tool_result` per `tool_use` and the verifier verdict; breakpoint on the last transcript block) → the stage instruction as a `system` message inside `Messages`, never in the top-level system field. `PromptEnvelope.SerializePrefix()`/`PrefixHash()` cover system + tools. `TokenBudgeter` counts with `IPromptTokenCounter` (`AnthropicTokenCounter` → `client.Beta.Messages.CountTokens`, falling back to `EstimatingTokenCounter`) and trims episodic entries, then the episodic block, then knowledge entries, then the knowledge block until under `Budgets:PromptTokens` (or the stage override); the count lands on `PromptEnvelope.InputTokens` and `AgentStep.PromptTokens`. `KnowledgeRetriever` uses `FREETEXT` on SQL Server when the Phase 3 migration created the full-text index (guarded on `IsFullTextInstalled`; LocalDB has none), else a `LIKE` filter on the query terms; candidates are scored in memory (question 3, tags 2, answer 1) and scoped by course (plus course-less entries) and module. `EpisodicMemoryStore` writes one `AgentEpisode` per completed run (`TaskText` from `TaskText.From(run)`, `Embedding` stored as JSON but not filled) and recalls same-task-type episodes of the run's course only, with trigram similarity, this learner first. `Compactor` is both modes: `ServerSideConfig` (`compact-2026-01-12`, input-token trigger at `Context:CompactAfterTokens`, requested once the counted prompt reaches that size) and `IEpisodeSummarizer` (Haiku at low effort, `ExtractiveSummarizer` fallback). `CacheHealthMonitor` records cache read/creation token counters on the `Intelligently.Agents` meter and counts/warns when a run repeats a prefix that was cached and reads zero cache tokens. Test hosts register `EstimatingTokenCounter` and `ExtractiveSummarizer` so no counting or summarizing reaches the network.
- **Execution Plane** — `IToolHandler.ExecuteAsync(call, ToolContext, ct)`; the `ToolContext` (run id, user, course, task type, principal) is what a tool may know about its run. `ToolDispatcher` evaluates the Control Plane for every call first, then executes the allowed calls of the turn: handlers run **concurrently** (`Task.WhenAll`), identical covered calls (same tool, same argument hash) are coalesced into one execution whose result every caller receives under its own `tool_use` id, and handlers whose descriptor is `Exclusive` run afterwards one at a time on the stage's DbContext. Each successful result is validated against the tool's `ToolDescriptor.OutputSchema` with JsonSchema.Net (a violation becomes an `is_error` result with `ErrorKind = OutputInvalid`, so Verify fails the step and Recover retries), covered results are recorded in the idempotency barrier and every outcome is traced, all results returned in call order; a throwing tool is an `is_error` result, never dropped. `StateGraphRunner` wraps every stage in one database transaction, so rows an exclusive tool saves mid-stage (an escalation, its receipt) commit together with the transition or not at all; the run lease is claimed before that transaction opens so other instances see it immediately. `ToolResult.Payload` carries the structured form of a result when there is one. `ToolRegistry` merges the registered `IToolHandler`s with every `IToolSource` (MCP). Native tools derive from `NativeTool<TInput, TOutput>` (input and output schemas exported from the C# records by `AgentJsonSchema`, which also copies `[Description]` onto properties): `run_lab_code` (ReadOnly; `ISandbox`; argv from `Agents:Sandbox:Languages`; compares stdout with `expected_output` when given), `create_escalation` (Mutating, course-scoped, exclusive; writes an `AIEscalation`), `notify_learner` (External, so it always needs approval, exclusive; records an `AIAnalyticsEvent` `LearnerNotified` until a real channel exists); `lookup_knowledge` is exclusive too and treats a null `course_id` as the run's course, never every course. `Execution/Mcp/McpToolSource` (singleton, connected by `McpToolSourceHostedService` before `RunWorker` starts) connects the servers in `Agents:Mcp:Servers` through `IMcpTransportFactory`, lists their tools and registers each as `server__tool` (the provider rejects dots in tool names) with `Strict = false`, risk `External` unless `Agents:Mcp:RiskOverrides` says otherwise; an unreachable server is a warning, not a startup failure. `Execution/Sandboxes/DockerSandbox` (default `ISandbox`; Docker.DotNet; throwaway container from `Agents:Sandbox:Image`, `network none`, memory/CPU/pids limits, all capabilities dropped, submitted files bind-mounted from a temp folder, wall-clock kill, stdout/stderr capped, container always removed; endpoint from config, `DOCKER_HOST`, or Docker Desktop's `dockerDesktopLinuxEngine` pipe when the classic pipe is absent) and `WasmSandbox` (Wasmtime; the first command element names the `.wasm` or WAT file among the request files; fuel, epoch-based timeout, linear-memory cap; WASI stdout/stderr to capped temp files) both implement `ISandbox` (`SandboxRequest`/`SandboxResult` in Core). Test hosts register a `FakeSandbox`; `DockerSandboxTests` use `[DockerFact]`, which skips when no engine answers a ping.
- **Evidence Plane** — `OtelEvidenceSink` (scoped, on the stage's DbContext) emits one root span per run (`agent.run`, started by `AgentRunService.CreateAsync`; its W3C ids are stored on `AgentRun.TraceId`/`RootSpanId` so every later stage span, on any worker, is parented on it), one child span per stage (`agent.stage.{Stage}`, with `agent.next_stage`/`agent.status` and the run totals on the terminal stage), and one grandchild per model call (`agent.model_call`: `gen_ai.request.model`, `gen_ai.request.effort`, `gen_ai.usage.*` per token class, `gen_ai.response.finish_reason`, `agent.cost_usd`, `agent.latency_ms`) and per tool call (`agent.tool_call.{name}`: tool name, `agent.tool.risk_level`, `agent.pdp.decision`, `agent.tool.is_error`, latency; a sandbox run also tags `agent.sandbox.exit_code`). Metrics on the `Intelligently.Agents` meter: `agent.tokens` (counter, tags model/stage/`agent.token_class` = input|output|cache_read|cache_creation), `agent.cost_usd` (counter, model/stage), `agent.stage.duration` (histogram, ms, stage/next stage). `TraceWriter` builds the append-only `AgentTrace` rows: `ModelCall` (payload = the exact envelope sent, the raw response, the response content blocks; columns `CostUsd`, `ReasoningSummary`, `StopReason`, `Effort`, `LatencyMs`, tokens per class), `ToolCall` (call, PDP decision, rule, risk level, result text and structured payload, latency, `StepId`) and `SandboxLog` (a result whose payload has `sandbox`/`exit_code`/`stdout`/`stderr`, recognised by shape so MCP sandboxes count too). Append-only is enforced by `IntelligentlyDbContext.SaveChanges`: a Modified or Deleted `AgentTrace` entry throws `AppendOnlyViolationException` (Core) before anything is written; corrections are new rows. The reasoning summary comes from `AnthropicReasoningEngine`, which sends `thinking: {type: adaptive, display: summarized}` and returns the thinking blocks' text, stop reason, effort and latency as `ModelCallMetadata` on `PlanResult`/`DecisionResult`/`JudgementResult`. `CostAccountant` (`ICostAccountant`, singleton) prices each token class from `Agents:Pricing:Models` (USD per million input, output, cache-read and cache-creation tokens per model id, exact or prefix match; seeded for `claude-opus-5-5` at 4 / 20 / 0.20 / 5 and `claude-haiku-5-5` at 0.10 / 0.50 / 0.01 / 0.125; an unpriced model costs 0 and logs once) and `Charge(run, usage)` adds the tokens and the cost to `AgentRun.TotalCostUsd`; when a run reaches Completed or Failed the runner calls `IEvidenceSink.FinishRunAsync`, which writes one `AIAnalyticsEvent` (`EventType = AgentRunFinished`, metadata = run id, status, tokens, cost, trace id) so existing reporting sees the totals.
- **Learn** — `Learn/EpisodeWriter` is the single place an `AgentEpisode` is written (transcript → `IEpisodeSummarizer` → `IEpisodicMemoryStore.WriteAsync`; a run gets exactly one episode, a second call returns it). `LearnHandler` calls it on completion. `IEscalationResolver`/`Learn/EscalationResolver.ResolveAsync(escalationId, instructor, response, addToKnowledgeBase)` is the instructor side: it resolves the `AIEscalation` (the existing `AddToKnowledgeBase` flag) and, when flagged, creates the `AIKnowledgeEntry` (question = learner question, answer = response, `SourceEscalationId`, entry type from the task type) and sets `AgentEpisode.KnowledgeEntryId`; an escalated run that never reached Learn gets its episode (Outcome Failed) through the same writer, and the link is recorded as a Learn-stage `Note` trace. One entry per escalation.
- **Budgets** — `CostAccountant.Charge` (via the `UsageAccounting` helper in Plan and Act) charges `input + cache_read + cache_creation` tokens (the provider reports them separately) plus output tokens to `TotalInputTokens`/`TotalOutputTokens` and the token budget. A spent hard budget is enforced before further model work: Interpret, Plan (before and after its call) and Verify (when steps remain) send the run to Recover with `RecoveryReason = BudgetExhausted`, which escalates.
- **Recover** — hard budget exhausted → escalate; oscillation (current plan hash equals one of the previous three revisions, or the current step failed twice with the same verifier message) → escalate; `StepFailed` with retries left → Act (RetriesLeft − 1); otherwise replans left → Plan (ReplansLeft − 1, PlanRevision + 1); else escalate.
- **Authentication** — both hosts call `services.AddIntelligentlyIdentity()` (`Infrastructure/Identity`): ASP.NET Core Identity (`IdentityUser`/`IdentityRole`, cookie) over `IntelligentlyDbContext`, login at `/Account/Login` (`/Account/Logout`, `/Account/AccessDenied`; accounts are provisioned out of band, there is no registration page), plus the `AgentAuthorization.InstructorPolicy` ("Instructor" role) policy. Browser requests that fail are redirected; JSON (`Content-Type`/`Accept: application/json`) and htmx (`HX-Request`) requests get a bare 401/403. `IntelligentlyClaims.ToRunPrincipal(ClaimsPrincipal)` is the only way a `RunPrincipal` is built from a caller: user id = `NameIdentifier`, roles = role claims, course scope = `intelligently:course` claims (one per enrolled course id, stored as Identity user claims until an enrolment entity exists). Nothing in a request body or form contributes to the principal.
- **Web** — every agent route requires an authenticated caller. `POST /agent/runs` (JSON, minimal API; body is `courseId`, `taskType`, `taskSpec` — a `userId` is ignored; 403 when the caller is not enrolled in the course), `GET /agent/runs/{id}` (Razor page; returns the `_RunStatus` htmx partial when the `HX-Request` header is present, polling while Running or Waiting; only the owning learner or an Instructor may see it, others get 403), `/agent` demo form (runs as the signed-in user, course must be in their enrolment), `RunWorker` background service (steps runs with `TryStepAsync` under its `IWorkerIdentity` and drops a run it could not claim; also re-enqueues Running runs at startup and, every `Agents:ApprovalSweepSeconds`, sweeps for approvals decided in Admin and for runs whose stage lease expired, so a duplicate enqueue on any instance simply fails to claim and a crashed worker's run is taken over).
- **Admin** — same DbContext, Anthropic client, `AddAgentRuntime` and `AddIntelligentlyIdentity` registrations as Web (no worker, so `IRunQueue` is replaced by `NoWorkerRunQueue`: enqueueing is a no-op and the Web sweep resumes decided runs). `/approvals`, `/escalations`, `/runs` and `/runs/{id}` carry `[Authorize(Policy = AgentAuthorization.InstructorPolicy)]`. `/approvals` lists pending `AgentApproval` rows with approve/deny htmx forms (`?handler=Approve|Deny`, antiforgery token required) and records `DecidedBy` as the signed-in user's name; `/escalations` lists escalations raised by agent runs with a resolve form (`?handler=Resolve`, fields `id`, `response`, `addToKnowledgeBase`) that goes through `IEscalationResolver`; `/runs` and `/runs/{id}` are read-only. The trace viewer shows the run (tokens, cost, trace id, episode and its knowledge link), plans with their planner calls, approvals, then per step the model call (`_ModelCall` partial: model, effort, stop reason, tokens per class, cost, latency, reasoning summary, prompt envelope, raw response and content blocks), each tool call (input, PDP decision, result, payload) and sandbox log (exit code, stdout, stderr), and finally every trace row; raw JSON is loaded on demand with htmx from `?handler=Trace&traceId=` (`_TracePayload` partial, 404 for a row of another run).
- **AIEscalation** now has a nullable `ConversationId` and an `AgentRunId` so agent runs can escalate without a chat conversation. `AgentRun` carries `TraceId`/`RootSpanId`; `AgentTrace` carries `CostUsd`, `ReasoningSummary`, `StopReason`, `Effort`, `LatencyMs` and the `SandboxLog` kind (migration `Phase5EvidencePlane`).
- Migrations live in `src/Intelligently.Infrastructure/Data/Migrations`; add one with `dotnet ef migrations add <Name> --project src/Intelligently.Infrastructure --startup-project src/Intelligently.Infrastructure --output-dir Data/Migrations` (a design-time factory supplies the context).
- Tests: `tests/Intelligently.UnitTests/Agents` run the real runtime on SQLite in-memory with a mocked `IReasoningEngine` (Context Plane: `ContextAssemblerTests`, `TokenBudgeterTests`, `EpisodicMemoryStoreTests`, `KnowledgeRetrieverTests`, `CompactionTests`, `CacheHealthMonitorTests`; the integration `StablePrefixEndpointTests` checks the prefix across turns in the Web host) (`StubTool` and `RecordingRunQueue` in `ControlPlaneStubs.cs` for Control Plane scenarios; `RunLeaseTests` drive two named workers through `AgentTestHost.TryStepAsync(runId, claimedBy)`; Execution Plane: `SandboxToolTests`, `DockerSandboxTests`, `WasmSandboxTests`, `McpToolSourceTests` against an `InProcessMcpServer` over pipes, `ParallelDispatchTests`, with `FakeSandbox`, `DockerFact` and the stub server in `ExecutionPlaneStubs.cs`; the integration `RunLabCodeEndpointTests` runs `run_lab_code` through the Web host's fake sandbox; Evidence Plane and Learn: `EvidencePlaneTests` (ActivityListener/MeterListener for the span hierarchy, attributes and metrics, append-only enforcement, sandbox log rows, the totals event), `CostAccountantTests`, `LearnStageTests`); `tests/Intelligently.IntegrationTests/Agents` hosts the Web app and `tests/Intelligently.IntegrationTests/Admin` hosts the Admin app with `WebApplicationFactory` the same way (the type parameter names a type from the entry assembly because both apps declare `Program`). Both factories register `TestAuthHandler` (`TestAuthentication.cs`) as the default scheme: a request is authenticated from the `X-Test-User`/`X-Test-Roles`/`X-Test-Courses` headers (`client.AsLearner("id", courses)`, `AsInstructor`, `As(...)`), or anonymous without them; challenges and forbids are forwarded to Identity's cookie scheme so the production redirect/401/403 behaviour is what tests see (`AgentAuthorizationTests`, `AdminAuthorizationTests`). The evaluation harness lives in `tests/Intelligently.IntegrationTests/Evals`: `TraceFixture` (a stored run: stages visited, steps, evidence rows, episode, expectations), `RubricEvaluator` (deterministic criteria: legal transitions, one transition row per stage, one priced model call per Plan/Act stage with stop reason, effort, latency and a reasoning summary, totals and budget arithmetic, a PDP decision per tool call, a sandbox log per sandbox call, then checks per outcome class completed | recovered | escalated) and `TraceReplayEvalTests` (`[Trait("Category", "Eval")]`), which replay the fixtures under `Evals/Fixtures` (`completed-lab-diagnosis`, `recovered-retry-after-skipped-tool`, `escalated-planner-exhausted`, copied to the output directory) and fail when a fixture or the whole set scores below `Evals:PassRateThreshold` from `Evals/evals.json` (0.95; override with the `INTELLIGENTLY_Evals__PassRateThreshold` environment variable). Add a fixture by exporting a known-good run's trace into the same JSON shape.

## Testing Stack

xUnit, Moq, FluentAssertions, coverlet for coverage. Agent tests use `Microsoft.EntityFrameworkCore.Sqlite` (in-memory) and `Microsoft.AspNetCore.Mvc.Testing`.
